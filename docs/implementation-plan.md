# Repeat 实施计划

版本：计划 v0.2。日期：2026-10-25。状态：**已按需求范围审查修订，开发任务尚未开始**。

依据：[功能需求 v0.2](requirements.md)、[技术方案 ADR-0001](decisions/0001-technical-selection.md)及[交互原型](index.html)。产品规则以需求文档为准，选型理由以 ADR 为准；本文负责工作顺序、任务拆分、依赖和验收。

## 1. 交付目标与当前起点

完成一个能够在其他应用中连续录制键鼠操作、保存原有节奏、编辑后实际执行的桌面工具。先交付 Windows 版本，再交付 Linux X11 版本；Wayland 单独验证。

当前目录仅有文档和独立 HTML 原型，没有 Tauri/Rust 工程、原生输入后端、正式数据存储或性能实测。原型可作为界面与交互基线，但其画布内监听、前端播放和 localStorage 不能直接承担原生录放。

实施顺序以最早证明核心能力为原则：先完成“三分钟跨应用录制 → 原节奏回放 → 全局停止”的最小闭环，再落实数据、编辑和完整桌面界面。

本次审查调整：提前接入真实数据下的编辑与三视图联动；把历史版本、录制中断恢复和未经测量的存储/绘制优化移出首轮必做范围。FR-01 至 FR-11 和 AC-01 至 AC-14 全部保留，完整 Windows 交付仍须覆盖这些要求。

### 已确认范围

| 项目 | 本轮确认的决定 |
| --- | --- |
| 技术方向 | 已确认 Tauri + Rust；其余选型见 ADR 建议，在 M1 验证后锁定 |
| 平台顺序 | Windows → Linux X11；Wayland 单独验证，不阻塞前两项交付 |
| 预览背景 | 用户手动导入参考图；首版不增加自动截图或同步屏幕录像 |
| 键盘与中文 | 忠实录放按键；新增或编辑文本单独处理，不要求自动识别输入法最终提交的中文 |
| 产品形态 | 连续录制、动作编辑和时间线；面向桌面窗口，不增加手机界面 |
| 首版功能依据 | FR-01 至 FR-11；工程可靠性要求按各阶段逐项落实 |

控件识别、自动寻找窗口、自动等待网页完成不属于当前已确认功能。循环执行、任务串联、导入导出和历史版本管理仍按第 6 节的建议与待定规则处理。

## 2. 阶段安排与依赖

| 阶段 | 交付结果 | 前置依赖 | 完成判断 |
| --- | --- | --- | --- |
| M0 最小验证准备 | 当前 Windows 环境记录、标准录制样本 | 无，可随 M1 补充 | 能开始同一套核心场景验证，不预建完整测试平台 |
| M1 Windows 原生验证 | 最小桌面工程、系统捕获与真实回放、全局停止、测量记录 | M0 的 Windows 验证环境 | 三分钟跨应用录放闭环可复现，核心路线有实测结论 |
| M2 保存与首次编辑试用 | 原始事件、当前编辑结果、本地保存及一条真实编辑路径 | M1 | 能定位动作、插入等待、保存重开并真实执行；原始记录可追溯 |
| M3 补全编辑与执行引擎 | 扩展同一套动作归并、编辑编译与调度 | M2 的可运行基础 | 各种已确认编辑均可执行，停止和失败行为可验证 |
| M4 补全桌面编辑器 | 完整原型交互、预览和时间线、独立演示 | 与 M3 按功能增量接入 | Windows 上通过完整功能验收 |
| M5 Windows 首版交付 | 稳定性与规模验证、安装包、使用说明 | M1–M4 | 在声明支持的 Windows 环境完成安装及回归 |
| M6 Linux X11 交付 | X11 后端、Linux 界面与安装验证 | M5；早期能力验证见下文 | 在声明支持的 X11 环境复用并通过相同验收 |
| M7 Wayland 独立验证 | 具体桌面环境的可行性结论及后续方案 | 独立选定验证环境 | 得到支持条件、限制或不可行证据；不默认形成支持承诺 |

交付主线为 **M0/M1 核心录放 → M2 首次编辑试用 → M3/M4 补齐功能 → M5 Windows 交付 → M6 X11 交付**。阶段不是要求逐层做完所有后端后才接界面：M2 就先接入 M3-02 的等待编辑和 M4-02 的共享视图，后续在同一实现上扩展，不另造一次性编辑器或第二套调度器。

M7 独立安排。只有遇到会影响当前数据模型的具体平台疑点，才提前做 M6-01 的最小 X11 验证；不为尚未使用的后端建设通用插件体系。完整 Linux 产品仍在 Windows 之后交付。

暂不承诺日历日期。M1 得到实际后端稳定性、计时误差和测试环境后，再估算后续工作量；不把未知的平台问题按普通界面功能估时。

## 3. 分阶段任务

以下复选框均为尚未执行的开发任务。每阶段完成时，应留下可运行交付物、验收结果和已知限制。

### M0：准备范围与验证材料

- [ ] **M0-01 验证环境。** 记录当前 Windows 实机的版本、架构、显示器/DPI、键盘布局和输入法。Linux 环境到其适配阶段再选；无需提前列出所有候选系统。
- [ ] **M0-02 标准样本。** 定义三分钟操作脚本，包含开头/中间/结尾停顿、移动、左右中键、单击/双击、上下滚轮、普通按键、组合键、长按重复、按住鼠标移动。优先使用现有测试页面或应用及无敏感信息的样本，不新建一套练习产品。
- [ ] **M0-03 最小测量。** 记录事件序号、单调时间、计划/实际注入时间及停止时间。M1 复用能记录 down/up、顺序和时间的接收页面或窗口；没有这样的工具时只补最小接收器，不建独立测试平台。目标最终显示正确不能代替事件级证据。
- [ ] **M0-04 决策登记。** 第 6 节按实际涉及的功能逐项定稿，在已有文档中记录即可；不把全部待定事项变成开工前置审批。

**验收：** 样本有明确步骤与预期；环境可复现；性能表只有目标和空白结果，不填入未经测量的数据。Windows 本机验证可先开展，尚未确定的其他系统版本不成为全部工作的阻塞项。

### M1：证明 Windows 原生录放可行

- [ ] **M1-01 最小工程。** 按 ADR 的默认建议建立 Tauri 2 + Rust + TypeScript/React/Vite 工程，锁定实际采用的依赖；沿用原型布局，先接通开始、停止、预览、执行和状态展示，不重新设计界面。仅开放必要的原生命令，补充实际可运行的开发说明。
- [ ] **M1-02 平台边界。** 将当前用到的 Windows 捕获、注入、坐标和停止操作隔离到小模块；不依赖界面组件或数据库。测试按需替换时钟或注入函数，不先实现完整模拟平台、通用后端注册或插件体系。
- [ ] **M1-03 系统捕获。** 验证低级键鼠钩子专用线程、消息循环、轻量回调和有界队列，保留时间、顺序、按下/抬起、位置、滚轮及单位。先验证选定方案；发现事件缺失、钩子失效、吞吐不足或无法解释的计时偏差时，再做 Raw Input 对照，不把两套捕获实现都列为开工门槛。
- [ ] **M1-04 最小真实回放。** 用原生单调时钟按绝对截止时间驱动 SendInput；检查实际注入数量，记录同时间戳事件顺序和三分钟累计漂移。不得由前端逐事件调度。
- [ ] **M1-05 全局停止与互斥。** 在任何真实注入测试前接通原生停止路径；窗口失焦时仍能停止。录制与系统执行互斥，预览不注入输入。定义录制控制快捷键的过滤范围，确保其按下/抬起不会混入可执行记录。
- [ ] **M1-06 当前环境边界。** 验证当前布局/输入法的按键序列、组合键、当前桌面坐标转换、权限受限目标和停止时的按键收尾。当前环境存在多屏/负坐标就处理；更多显示布局、输入法及强制结束表现放到 M5 的支持范围验证，不在 M1 承诺全面兼容。

**验收：** 在 Repeat 之外录制标准样本并按原节奏回放；有事件接收记录可核对按下/抬起、顺序、原有停顿和停止行为；得到 POC-01、POC-04 在当前环境的首轮结果及性能基线。若现有路线不能满足系统录制或及时停止，先解决或调整后端；不以肉眼看到最终效果代替输入保真验证。

此阶段需要优先验证而非直接承诺：Windows 低级钩子存在超时失效问题；SendInput 受完整性级别限制，返回结果不能单独确诊 UIPI 拦截。[Microsoft 低级键盘钩子说明](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)、[SendInput 说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。

### M2：保存与首次编辑试用

- [ ] **M2-01 必要数据。** 在逻辑上区分原始事件、动作视图和当前编辑结果，不要求各自建独立持久化系统。保留稳定 ID、时间、序号、桌面几何、布局和用于拒绝过期编辑的递增修订号；修订号不代表保留每次编辑历史。单独保存录制起止时长，不能截掉结尾停顿。
- [ ] **M2-02 最小可靠保存。** 默认沿用 SQLite，保存任务、原始事件、当前编辑结果和格式版本。先在已验证规模内使用简单序列化，录制结束后在捕获线程之外保存；任务内容和完成状态事务提交，写失败不报成功。参考图保存到应用管理的数据位置。分块/索引/持续落盘有测量依据后再加，不另造通用存储框架。
- [ ] **M2-03 有效数据保护。** 新录制成功提交后才替换当前内容，取消或失败保留旧内容；编辑取消不写入。未成功保存的录制不能标为已保存。首轮不承诺找回进程中断前的未保存内容，不额外建设历史版本、回收站或恢复界面；持续恢复能力按第 6 节另定。
- [ ] **M2-04 任务隔离与首次试用。** 实现任务新建、重命名、加载和保存，防止旧任务异步结果覆盖新任务。按操作需要校验任务、修订和会话标识。接入真实录制的动作列表、预览和简版时间线，完成“选择定位 → 插入一秒等待 → 保存重开 → 实际执行”；这是 M3/M4 的首个增量，沿用同一数据、编译与调度路径。其余编辑和界面随后补齐。

首次等待编辑即须包含最小校验：统一延后鼠标和键盘的后续时间，保留原停顿；先只接受按下/抬起已闭合且没有动作跨越的插入边界，其他重叠边界拒绝并说明原因。取消不改数据，确认后才执行相应结果。这些正确性检查与试用一起接入，不能等到 M3 再补。

**验收：** 用户能用真实数据试用上述编辑路径；两个任务切换、保存和重启后保持独立；重新读取后事件及起止时长一致；等待同步影响所有轨道、不吞原停顿，未通过边界校验的编辑不能进入执行。中断写入或写入失败不能破坏已保存任务，也不能显示保存成功。本阶段试用不代替 M4 的完整功能验收。

### M3：补全动作编辑和执行引擎

- [ ] **M3-01 动作归并。** 将连续移动、点击/双击、同向滚轮、按键及组合键整理为可读动作，保留原始事件引用。拖拽的按住/抬起和交错键鼠事件不能因归并丢失；无法确定的文本显示为按键事实。
- [ ] **M3-02 编辑编译。** 在 M2 已接通的等待编辑上扩展移动终点/耗时、点击按键/次数/坐标、滚轮方向/数量和键盘输入。原始数据不被覆盖；从当前编辑结果生成执行序列，校验顺序、坐标、时间与键鼠状态，不持久化每次编译产物。移动与后续点击只有明确选择联动时才一起变化。
- [ ] **M3-03 时间与重叠语义。** 插入等待时统一移动鼠标和键盘后续时间，保留原有停顿；修改耗时也必须给出一致的后续时间映射。对跨越编辑边界的按住、拖动和组合键先检测；首轮建议拒绝会拆开有效输入状态的编辑并解释原因，不静默补出按键事件。
- [ ] **M3-04 明确文本输入。** 将用户新增/编辑的文本与录制按键分成不同动作来源。验证字符注入、中文、换行、符号及目标应用支持；不默认通过剪贴板粘贴，不把任意输入法提交内容当成已采集文本。
- [ ] **M3-05 会话与调度。** 扩展 M1 的同一调度器，完成空闲、准备、录制、预览、执行、停止和失败状态；按当前修订生成执行序列，执行中不接受改变该序列的编辑。补齐可取消等待、延迟过大处理、部分注入失败、挂起/会话切换和本次注入按键的收尾规则。状态可用简单枚举表达，不引入通用工作流引擎。

**验收：** POC-02 通过。编辑后列表、预览与系统执行使用同一份修订；修改终点与联动点击结果可核对；插入 1 秒等待后后续时间和总时长增加 1 秒，原停顿不变；双击仍是两次完整按下/抬起；停止后不再发出新的计划输入。初始已有按键按住或停止时存在未闭合事件，应明确处理，不能悄悄生成一份无法解释的执行计划。

### M4：补全桌面编辑器

- [ ] **M4-01 工作区与任务。** 在前面已接通的界面上，按原型补齐左侧任务、右侧预览、录制内容、菜单和编辑窗口，包括明确文本输入入口及任务删除的必要规则。将“预览”和“执行到系统”作为清楚区分的入口；运行状态由 Rust 驱动，录制结束后加载实际数据。
- [ ] **M4-02 统一视图状态。** 扩展 M2 的共享时间与动作选择，实现所有动作的单击定位、双击编辑、取消/确认。原型的会话内撤销重做可以复用，是否纳入首版按第 6 节定稿；不借此增加跨重启历史版本系统。异步返回的旧任务快照不能覆盖当前任务。
- [ ] **M4-03 参考图与坐标。** 支持手动导入并显示图片来源，记录图像与录制桌面的映射；等比显示、留白、多屏原点、缩放和预览选点使用同一转换。参考图仅用于查看和选点，不自动识别图中控件；无图时仍能使用预览。
- [ ] **M4-04 连续时间线。** 沿用原型交互，补齐密集标记、完整悬停信息、滚轮围绕指向时间缩放、加减缩放及适合窗口。先缓存当前任务并绘制可见部分，不每帧查库，不为每个移动采样建立 DOM；Canvas、分页与专门的命中索引在实际规模出现瓶颈时再引入。录制期间范围持续增长，结束标记完整可见；面板显隐只影响布局，不改变数据和时间。
- [ ] **M4-05 帮助与桌面适配。** 将引导和练习放在独立演示空间，退出恢复原任务；保留键盘操作及桌面小窗口可用性。导出原型演示数据的逻辑不自动成为正式产品数据格式。

**验收：** 在 Windows 实际 WebView 中通过 AC-01 至 AC-14；原生相关场景调用真实后端。重点核对三处时间同步、录制超过五秒后的适合窗口、视图菜单显隐、取消编辑、任务隔离与演示退出。

原始输入采集与执行留在 Rust，界面接收动作/轨迹摘要和小型进度快照。规模需要流式通信时再采用 Channel，数据量需要时再增加分批加载或范围查询；普通 Tauri 事件通道不承担高吞吐输入热路径。[Tauri 前后端通信说明](https://v2.tauri.app/develop/calling-frontend/)。

### M5：完成 Windows 稳定性验证与交付

- [ ] **M5-01 性能与规模。** 复测三分钟基线、高频移动、界面繁忙；按实际使用时长增加长录制样本，记录 CPU、内存、磁盘增长和交互延迟。只有实测超过约定预算才引入相应存储/绘制优化；不能因省掉优化而无提示截断录制。
- [ ] **M5-02 兼容与失败。** 按实际声明支持的显示布局、DPI、输入法和目标应用验证；覆盖队列溢出、写入失败、过期编辑、部分注入、快捷键冲突、环境变化、挂起和用户主动停止。发生错误时保护已保存数据并给出原因，不静默丢事件或补发过期点击。进程强制结束的限制单独记录，不默认增加看护进程。
- [ ] **M5-03 安装验证。** 构建包含本地静态资源的 Windows 安装包，在干净环境检查安装、启动、WebView2 依赖、任务保存重开及卸载的数据处理；正常使用无需开发服务。存在已发布旧格式时才实现相应迁移，不为首版提前建设自动升级或签名发布流水线。
- [ ] **M5-04 交付材料。** 提供安装包、首次使用说明、已测环境、功能/性能结果及限制；正文不将未验证系统列为支持。普通日志不记录完整键盘文本，不自动上传录制数据。

**验收：** FR/AC 对应功能完成，严重录放和数据问题关闭，原节奏可复现且没有逐步额外等待导致的累积变慢。性能提供实测结果；已经约定的数值门槛须通过，ADR 中未确认的试验数字不自动成为新增发布条件。公布支持范围及尚未验证项；Windows 完成后，Linux X11 仍是后续交付任务。

### M6：交付 Linux X11

- [ ] **M6-01 小样验证。** 在指定 X11 环境检测 RECORD、XTEST、连接权限和 XKB，验证捕获、回放、停止及坐标。默认在 Linux 阶段开展；当前数据模型遇到具体平台疑点时只提前验证该疑点。
- [ ] **M6-02 平台接入。** 在相同引擎接口下接入 X11，独立处理键码/布局/修饰键、滚轮和桌面几何，不直接复用 Windows 扫描码或原生滚轮单位。明确本会话按键数据的适用条件。
- [ ] **M6-03 桌面和安装。** 验证 WebKitGTK 中的时间线、参考图、编辑窗口、菜单和全局停止；选择候选发行版对应的包格式及依赖，并完成干净环境安装。
- [ ] **M6-04 全量回归。** 在承诺支持的环境执行与 Windows 相同的功能和性能场景，记录差异与限制；只验证 XWayland 应用不能算作覆盖整个 Wayland 桌面。

**验收：** 指定 Linux X11 环境中跨应用录放、编辑、停止、保存、重启读取已保存任务及安装全部通过；有独立实测结果。跨操作系统复用录制文件尚未确认，不能由两套后端都可运行推导出跨平台录制兼容。

### M7：单独验证 Wayland

- [ ] **M7-01 环境与能力。** 选择具体 GNOME/KDE 等桌面、版本及授权方式，分别调查正常桌面操作期间的捕获、输入注入、桌面坐标和停止能力。
- [ ] **M7-02 端到端证据。** 用小样验证允许用户继续正常操作的连续录制、原节奏回放、终点编辑及权限撤回。Portal 或设备接口“可以调用”不等于整条链路成立。
- [ ] **M7-03 结论与下一步。** 输出可行环境、需要的授权、限制及维护成本；若不能满足既定交互，记录不可行原因和替代选项。只有验证成立后才另订产品适配计划。

**验收：** 有可复现的可行或不可行结论。官方 InputCapture 有启用与激活的区分，且激活会改变输入的接收方式；据此，不能直接把该接口当作通用的桌面输入旁听功能。这是安排独立验证的依据。[XDG InputCapture 文档](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.InputCapture.html)。

## 4. 建议的工程组织与接口约束

以下是职责边界，不是要求预先创建全部目录。先使用一个应用工程，具体文件随实际代码增长再拆分。

| 范围 | 负责内容 |
| --- | --- |
| 前端 `src/` | 沿用原型交互，维护任务、编辑、预览、时间线和演示共享状态 |
| Rust 引擎 | 事件数据、动作归并、编辑编译、会话状态、调度及停止 |
| 平台调用模块 | 先隔离实际用到的 Windows API，接入 X11 时再提取确实共用的接口 |
| 本地保存与测试 | 简单事务保存；随对应功能补固定事件样本、最小接收验证及必要错误路径测试 |

关键约束在 M1/M2 确定，后续阶段沿用：

1. **事件与时间。** 相对单调时间和事件序号共同确定顺序；保存独立录制时长。UI 时间换算不能损失输入顺序或吞掉原始停顿。
2. **来源与修订。** 区分真实录制、编辑结果、明确文本输入及练习数据。简单修订号用于拒绝过期操作，执行固定到当前编译结果；不要求持久化所有历史修订。
3. **会话状态。** Rust 管理录制与执行互斥及停止；界面只提交控制请求和展示状态。停止通路不依赖 UI 下一帧。
4. **数据传输。** 按操作需要校验任务/会话/修订；原始输入留在原生路径，界面取得动作与轨迹摘要。先用缓存和少量快照，可合并视图更新，不能静默丢弃原始事件。
5. **坐标与布局。** 明确桌面原点、显示器几何、DPI、图像映射和键盘布局。环境不匹配时按明确规则处理，不能偷偷猜测目标。

## 5. 验收与测试安排

### 需求覆盖

| 需求/场景 | 主要完成阶段 | 必须保留的证据 |
| --- | --- | --- |
| FR-01；AC-07 的任务部分 | M2、M4 | 两任务切换、编辑、重启后数据隔离 |
| FR-02、FR-03；AC-01、AC-02、AC-03 | M1、M3、M5、M6 | 三分钟跨应用捕获/回放记录、完整事件核对和注入结果 |
| FR-04；AC-04 | M3、M4 | 高频移动归并、终点编辑、原始轨迹可追溯 |
| FR-05；AC-05、AC-06 | M2 首次试用，M3/M4 补齐 | 取消无变更、确认修订一致、等待与原停顿同时保留 |
| FR-06、FR-07；AC-08、AC-13 | M2 首次试用，M3/M4 补齐 | 真实动作表达、共享时间、预览与执行入口隔离 |
| FR-08；AC-09、AC-14 | M4、M5 | 缩放锚点正确、录制中适合窗口、末尾完整可见 |
| FR-09；AC-10 | M4 | 面板独立显隐、空间回收、数据与时间不变 |
| FR-10；AC-07 的演示部分、AC-11 | M4 | 引导可跳过、练习隔离、退出恢复 |
| FR-11；AC-12 | M4、M5、M6 | 约定最小桌面窗口与平台 WebView 的实际操作记录 |

### 验证层次

- **数据与编辑测试：** 固定事件样本验证同时间戳顺序、跨轨道按住状态、双击、方向变化、终点联动、等待/耗时映射、编辑取消及修订冲突。优先覆盖可能改变真实执行结果的逻辑。
- **调度测试：** 用最小可替换时钟/注入函数验证截止时间、取消、延迟过大和部分失败；用真实操作系统及接收页面/窗口核对事件。模拟测试不替代原生结果，不要求完整模拟平台。
- **存储测试：** 用临时数据库验证事务、事件往返、任务隔离以及写失败/中断写入时旧数据仍有效。历史格式迁移、录制中断恢复的测试随相应能力引入，不预建尚未使用的测试体系。
- **界面测试：** 对 AC-05、AC-07 至 AC-14 做真实桌面交互回归；静态构建成功不等于录放通过。保留关键窗口尺寸与密集时间线的检查记录。
- **平台测试：** Windows 和 Linux 分别列 OS/会话、硬件、显示器/DPI、输入法、目标应用、负载和事件规模；没有在某个平台跑过的结果标记为未验证。

性能初轮沿用 [ADR 第 6 节的工程目标](decisions/0001-technical-selection.md#6-低延迟与原生调度)：注入时间绝对偏差 P95 ≤ 5 ms、P99 ≤ 15 ms，三分钟累计漂移绝对值 ≤ 20 ms，原生停止信号到停止新注入 P95 ≤ 50 ms。**这些仍是待实测和确认的目标，不是已实现数值，也不是本轮用户新增确认的要求。** 同时记录最大值、负载条件、事件完整性及按键收尾。

任何平台交付均须满足：功能可复现、数据没有静默丢失、输入失败不假报成功、支持范围与实测一致。目标应用收到输入后的业务处理速度单独观察，不拿引擎注入成功替代。

## 6. 其余决策及建议默认值

本轮三个范围问题已确认；下表保留仍会影响实现的事项。建议用于细化计划，**不等于用户已经确认**。到相应阶段定稿即可，不需同时阻塞全部工作。

| 事项 | 建议默认值或处理原则 | 最晚决定时点 |
| --- | --- | --- |
| Windows 版本/架构、Linux 发行版 | 首轮使用当前 Windows 实机；发布前明确经过验证的系统与架构。Linux 先选一个明确的 X11 环境 | M0/M1 确定测试机，M5/M6 确定承诺范围 |
| 预览和执行命名 | “预览”只看内容；“执行到系统”实际操作。执行前由用户准备目标应用和焦点 | M1 原生验证前确定最小入口，M4 定稿文案 |
| 全局快捷键及人工介入 | 录制启停暂沿用原型 F8；系统执行设置全局主动停止键并检测冲突。执行前验证停止可用；自动检测人工输入并中止尚未确认，不默认为首版功能 | M1 前确定主动停止；自动介入另定 |
| 回放次数与失败策略 | 首版默认单次；失败停止并报告，不自动重试点击、不自动找控件。循环、无限循环和任务串联以后另定 | M3 |
| 编辑时间边界 | 插入等待保持原停顿；改变动作耗时联动后续时间。涉及跨边界按住/重叠时检测冲突，不能成立的编辑拒绝保存 | M3 |
| 重录、删除与撤销 | 新录制成功提交后才切换当前内容，取消/失败保留旧内容；这不等于成功后另存旧版本。删除保护及原型会话内撤销/重做按需定稿，历史版本和回收站不作为首版默认要求 | M2 先保证有效数据保护；M4 定稿交互 |
| 导入导出 | 建议首版先完成本地任务可靠保存；正式文件交换格式另定，不直接接收原型 JSON 作为可执行录制 | M2 存储设计时 |
| 规模与恢复窗口 | 先测三分钟基线，再按实际时长/内存预算决定分块与持续落盘。已保存数据必须可靠；未保存录制的中断恢复在有明确需求后单列，不以无限录制或零丢失为默认承诺 | M2 基线，M5 确定已验证规模；恢复诉求另定 |
| 额外输入 | 拖动涉及的原始按住/抬起必须保留；拖拽独立编辑、水平滚轮、侧键是否提供首版完整支持另定，未支持的输入明确提示 | M1 能力记录，M3 编辑范围定稿 |
| 输入法与文本适用范围 | 保留按键录放与明确文本动作的分工；布局、输入法及文本注入适用的目标应用按实测列出 | M1 首轮验证，M3/M6 完成支持表 |
| 安装与发布 | 首版提供可安装、可保存重开的本地包并明确卸载数据处理；需要公开分发或出现真实旧版本时再落实相应签名、升级和迁移工作 | M5/M6；后续机制按实际发布需求 |
