# Repeat 实施计划

版本：计划 v0.6。日期：2026-10-26。状态：**Windows 录制、保存、动作编辑、预览与系统执行已接通，当前为试用实现；键盘编辑末轮检查按用户要求跳过。第三轮按交互原型收敛空任务态、预览、侧栏、时间线、编辑窗口、三段式引导与画布内演示；各项任务的完成状态未因此改变。完整交付验收尚未完成，结果与边界见第 8 节。**

依据：[功能需求 v0.3](requirements.md)、[技术方案 ADR-0001](decisions/0001-technical-selection.md)及[交互原型](index.html)。产品规则以需求文档为准，选型理由以 ADR 为准；本文负责工作顺序、任务拆分、依赖和验收。

## 1. 交付目标与当前起点

完成一个能够在其他应用中连续录制键鼠操作、保存原有节奏、编辑后实际执行的桌面工具。先交付 Windows 版本，再交付 Linux X11 版本；Wayland 单独验证。

当前仓库已包含 Windows 原生输入引擎、SQLite 任务保存、动作归并与编辑编译、会话内撤销重做，以及接入真实数据的桌面编辑器。系统捕获与执行由 Rust 管理；原型仅作为交互基线，其画布监听、前端播放和 localStorage 不承担原生录放。

当前不是仅有 M1 演示的版本，也尚不能视为完成 M5 的正式 Windows 交付。短混合输入、三分钟移动与停顿、明确文本、停止收尾及应用内三轮执行已有原生证据；这些场景分别验证，不合并描述为“三分钟混合操作全量验收通过”。最后一次键盘编辑检查按用户要求跳过，安装、兼容与规模验收仍有剩余项。

实施顺序以最早证明核心能力为原则：先完成“三分钟跨应用录制 → 原节奏回放 → 全局停止”的最小闭环，再落实数据、编辑和完整桌面界面。

本次审查调整：提前接入真实数据下的编辑与三视图联动；把历史版本、录制中断恢复和未经测量的存储/绘制优化移出首轮必做范围。FR-01 至 FR-11 和 AC-01 至 AC-15 全部保留，完整 Windows 交付仍须覆盖这些要求。

暂不承诺日历日期。后续工作依据已有验证结果与剩余平台问题安排，不把未知的平台问题按普通界面功能估时。

### M2：保存与首次编辑试用

- [x] **M2-01 必要数据。** 在逻辑上区分原始事件、动作视图和当前编辑结果，不要求各自建独立持久化系统。保留稳定 ID、时间、序号、桌面几何、布局和用于拒绝过期编辑的递增修订号；修订号不代表保留每次编辑历史。单独保存录制起止时长，不能截掉结尾停顿。（2026-10-26：已实现；原始事件、动作来源、当前修订与独立起止时长由 Rust 管理。）
- [x] **M2-02 最小可靠保存。** 默认沿用 SQLite，保存任务、原始事件、当前编辑结果和格式版本。先在已验证规模内使用简单序列化，录制结束后在捕获线程之外保存；任务内容和完成状态事务提交，写失败不报成功。参考图保存到应用管理的数据位置。分块/索引/持续落盘有测量依据后再加，不另造通用存储框架。（2026-10-26：已实现；SQLite 事务、格式版本拒绝、删除失败回滚与保存往返有单元测试，任务与参考图已在应用中保存重开。）
- [x] **M2-03 有效数据保护。** 新录制成功提交后才替换当前内容，取消或失败保留旧内容；编辑取消不写入。未成功保存的录制不能标为已保存。首轮不承诺找回进程中断前的未保存内容，不额外建设历史版本、回收站或恢复界面；持续恢复能力按第 6 节另定。（2026-10-26：已实现；放弃录制保留原任务已有实际界面核对，保存失败保留待处理数据，不假报保存成功。）
- [x] **M2-04 任务隔离与首次试用。** 实现任务新建、重命名、加载和保存，防止旧任务异步结果覆盖新任务。按操作需要校验任务、修订和会话标识。接入真实录制的动作列表、预览和简版时间线，完成“选择定位 → 插入一秒等待 → 保存重开 → 实际执行”；这是 M3/M4 的首个增量，沿用同一数据、编译与调度路径。其余编辑和界面随后补齐。（2026-10-26：已完成两任务切换和重启读取；真实任务插入 1 秒等待后保存，并由应用启动三轮系统执行，结果见第 8 节。）

首次等待编辑即须包含最小校验：统一延后鼠标和键盘的后续时间，保留原停顿；先只接受按下/抬起已闭合且没有动作跨越的插入边界，其他重叠边界拒绝并说明原因。取消不改数据，确认后才执行相应结果。这些正确性检查与试用一起接入，不能等到 M3 再补。

**验收：** 用户能用真实数据试用上述编辑路径；两个任务切换、保存和重启后保持独立；重新读取后事件及起止时长一致；等待同步影响所有轨道、不吞原停顿，未通过边界校验的编辑不能进入执行。中断写入或写入失败不能破坏已保存任务，也不能显示保存成功。本阶段试用不代替 M4 的完整功能验收。

- [x] **M3-01 动作归并。** 将连续移动、点击/双击、同向滚轮、按键及组合键整理为可读动作，保留原始事件引用。拖拽的按住/抬起和交错键鼠事件不能因归并丢失；无法确定的文本显示为按键事实。（2026-10-26：已实现原生动作投影与来源引用；连续移动、同向滚轮及重复按下归并，拖拽、侧键和水平滚轮完整保留并标注编辑限制。）

- [x] **M3-03 时间与重叠语义。** 插入等待时统一移动鼠标和键盘后续时间，保留原有停顿；修改耗时也必须给出一致的后续时间映射。对跨越编辑边界的按住、拖动和组合键先检测；首轮建议拒绝会拆开有效输入状态的编辑并解释原因，不静默补出按键事件。（2026-10-26：已实现并覆盖等待闭合边界、交错键鼠冲突、同时间戳顺序与耗时映射测试；应用内等待编辑已有真实执行核对。）
- [x] **M3-04 明确文本输入。** 将用户新增/编辑的文本与录制按键分成不同动作来源。验证字符注入、中文、换行、符号及目标应用支持；不默认通过剪贴板粘贴，不把任意输入法提交内容当成已采集文本。（2026-10-26：标准 Windows EDIT 控件中已验证中文、ASCII、emoji、符号和换行，重复三轮；这是明确文本输入验证，不代表任意输入法或所有目标应用兼容。）
- [ ] **M3-05 会话与调度。** 扩展 M1 的同一调度器，完成空闲、准备、录制、预览、执行、停止和失败状态；按当前修订生成执行序列，执行中不接受改变该序列的编辑。执行支持按填写次数循环（默认 10 次），轮间不额外插等待，任一轮失败即停止并报告第几轮。补齐可取消等待、延迟过大处理、部分注入失败、挂起/会话切换和本次注入按键的收尾规则。状态可用简单枚举表达，不引入通用工作流引擎。（2026-10-26：会话、循环、可取消等待、严重延迟停止与收尾已实现，三轮执行和原生全局停止已验证；环境消息取消测试通过，实际锁屏、挂起和显示环境切换仍待验收。）

## 4. 建议的工程组织与接口约束

以下是职责边界，不是要求预先创建全部目录。先使用一个应用工程，具体文件随实际代码增长再拆分。

| 范围           | 负责内容                                                               |
| -------------- | ---------------------------------------------------------------------- |
| 前端 `src/`    | 沿用原型交互，维护任务、编辑、预览、时间线和演示共享状态               |
| Rust 引擎      | 事件数据、动作归并、编辑编译、会话状态、调度及停止                     |
| 平台调用模块   | 先隔离实际用到的 Windows API，接入 X11 时再提取确实共用的接口          |
| 本地保存与测试 | 简单事务保存；随对应功能补固定事件样本、最小接收验证及必要错误路径测试 |

关键约束在 M1/M2 确定，后续阶段沿用：

1. **事件与时间。** 相对单调时间和事件序号共同确定顺序；保存独立录制时长。UI 时间换算不能损失输入顺序或吞掉原始停顿。
2. **来源与修订。** 区分真实录制、编辑结果、明确文本输入及练习数据。简单修订号用于拒绝过期操作，执行固定到当前编译结果；不要求持久化所有历史修订。
3. **会话状态。** Rust 管理录制与执行互斥及停止；界面只提交控制请求和展示状态。停止通路不依赖 UI 下一帧。
4. **数据传输。** 按操作需要校验任务/会话/修订；原始输入留在原生路径，界面取得动作与轨迹摘要。先用缓存和少量快照，可合并视图更新，不能静默丢弃原始事件。
5. **坐标与布局。** 明确桌面原点、显示器几何、DPI、图像映射和键盘布局。环境不匹配时按明确规则处理，不能偷偷猜测目标。

### 验证层次

- **数据与编辑测试：** 固定事件样本验证同时间戳顺序、跨轨道按住状态、双击、方向变化、终点联动、等待/耗时映射、编辑取消及修订冲突。优先覆盖可能改变真实执行结果的逻辑。
- **调度测试：** 用最小可替换时钟/注入函数验证截止时间、取消、延迟过大和部分失败；用真实操作系统及接收页面/窗口核对事件。模拟测试不替代原生结果，不要求完整模拟平台。
- **存储测试：** 用临时数据库验证事务、事件往返、任务隔离以及写失败/中断写入时旧数据仍有效。历史格式迁移、录制中断恢复的测试随相应能力引入，不预建尚未使用的测试体系。
- **界面测试：** 对 AC-05、AC-07 至 AC-14 做真实桌面交互回归；静态构建成功不等于录放通过。保留关键窗口尺寸与密集时间线的检查记录。
- **平台测试：** Windows 和 Linux 分别列 OS/会话、硬件、显示器/DPI、输入法、目标应用、负载和事件规模；没有在某个平台跑过的结果标记为未验证。

性能初轮沿用 [ADR 第 6 节的工程目标](decisions/0001-technical-selection.md#6-低延迟与原生调度)：注入时间绝对偏差 P95 ≤ 5 ms、P99 ≤ 15 ms，三分钟累计漂移绝对值 ≤ 20 ms，原生停止信号到停止新注入 P95 ≤ 50 ms。**这些是内部自检目标，不作为用户验收门槛；已有样本的实际结果见第 8 节，不外推到未测负载与平台。** 同时记录最大值、负载条件、事件完整性及按键收尾；停止的单次样本不能当作 P95。

任何平台交付均须满足：功能可复现、数据没有静默丢失、输入失败不假报成功、支持范围与实测一致。目标应用收到输入后的业务处理速度单独观察，不拿引擎注入成功替代。

### 实现与界面整理

- Windows 原生捕获与调度、SQLite 保存、任务隔离、动作编辑编译、会话内撤销重做、参考图、预览与系统执行使用同一任务修订；录制与系统执行互斥。
- 操作入口去掉阶段占位说明；动作列表以动作与持续时间表达内容，原始事件数移到“关于 Repeat”的诊断信息。预览到末尾自动暂停；演示空间与真实任务隔离。
- 修复开发启动时 `actions.ts` 缺少 `buildDisplayRows` 导出的错误，真实 Tauri WebView 已能够加载工作区。
- README 只保留介绍、使用方式和入口；阶段状态、结果和剩余事项在本文维护。本轮末尾仅整理文档，没有追加功能改动或复验。

截图中的“几千个采样”是原始钩子事件数，与列表中归并后的动作数不同。高频移动会产生大量位置事件；仅凭这个数量不能判断录制异常，也不能据此认定某个硬件回报率，本轮没有单独测鼠标硬件回报率。原始轨迹和停顿保留在 Rust 与本地任务中，界面按动作归并并限制轨迹绘制点数，绘制简化不删除原始记录。后续是否需要存储或调度优化，由实际规模测量决定。

### 第二轮（2026-10-26）：键盘编辑缺陷修复、界面原型对齐与打包

本轮按用户指令推进，仅落地可在本机无人值守完成的实现项：修复键盘编辑中已定位的保持性缺陷（终轮审查本身仍按用户要求跳过，不因此标记任务完成）；按用户对界面截图的复核意见对齐交互原型视觉。多屏、权限受限目标、真实锁屏/挂起、长时规模测量及 Linux/Wayland 仍需真实环境，未列入本轮。

**实现改动：**

- 键盘编辑保持性缺陷修复（代码级，附单元测试）：`parse_chord` 补齐 `vk_name` 会生成的特殊键名——Pause、CapsLock、PrtSc、菜单、小键盘 0-9 与 `* + - . /`、全部标点（`;` `=` `,` `-` `.` `/` `` ` `` `[` `\\` `]` `'`）及 `#键码` 形式，录制动作的按键名可解析往返；"小键盘+"名称中的 `+` 不再被误拆为组合键分隔符。`updateKeys` 在和弦与现有动作一致时原样确认、不重建事件，保留重复按下、原始扫描码与真实按下/抬起时间。以上不作为终轮审查完成的证据，M3-02 保持未完成。
- 按用户对界面截图的复核意见重写 `src/App.css`，把原型的设计体系移植到真实应用：灰色画框（`--frame`）+ 白色圆角工作卡片、透明任务侧栏、40px 品牌标题栏（repeat 图标 + Repeat + 右侧说明）、完整的 token 集（`--raised/--active/--rule/--accent-soft/--wait-*` 等）、按钮体系（34px 主按钮为墨色、无边框 icon 按钮）、菜单弹层、对话框（64px 标题栏 + 24px 内容 + 横贯底栏）、状态条配色、通知/练习区样式及与原型一致的三个响应式断点。
- 时间线画布重绘为原型视觉语言：28px 刻度尺（圆点刻痕 + 居中标签）、覆盖鼠标与键盘轨道的圆角连续 ribbon（#eff4f6 底 + #d9e3e7 边）、移动动作胶囊 + 下划线、点击动作的指针标记（双击加两点）、键盘动作白色芯片、等待块米色底、带圆点顶的红色播放头、结束标记；等待轨道仅在任务含等待时出现（轨道标签同步显隐）。缩放、平移、双击编辑等行为未改动。
- 组件微调：标题栏品牌与"键鼠录制"说明、任务列表行加文件夹图标、预览画布四周留白（#fafafa 视口内衬屏幕区）、图标库新增 repeat 循环图标。行为与数据路径未改动。
- 前端把编辑窗口的请求构造提取为纯函数 `buildEditRequest`（`src/editor.ts`），组件只维护表单状态；并补齐覆盖全部动作类型（等待/移动/点击/滚轮/键盘/文本/插入）及不可编辑动作拦截的单元测试。
- 窗口最小尺寸（M4-05 范围）设为 976×680，保证 WebView 视口不低于此前已验证的 960×640。
- 时间线补"录制中范围增长时视图收敛"单元测试（M4-04 范围）。

**WebView 核对：** 已在 `pnpm tauri dev` 实际 WebView 截图核对界面原型对齐：整体布局、时间线、侧栏与播放器栏与原型一致，无破版。对话框与编辑交互因后台焦点策略拒绝合成输入，未做逐项操作回归；相关阶段任务不因截图核对标记完成。

### 第三轮（2026-10-26）：按原型收敛工作区、引导与演示

本轮以 [交互原型](index.html) 为基线重做界面结构与交互；录放引擎、数据格式和执行调度未改。用户随后提出的“执行前无需切换应用”“录制时自动带屏幕背景”“Cap 式录制状态”尚在讨论，未在本轮实现；现有的 3 秒准备与手动参考图逻辑保持原样。

**实现改动：**

- 空任务态：隐藏预览画面、播放器、时间线和录制内容，居中显示“还没有录制 / 点击右上角的开始录制”；任务头部只保留开始录制与任务菜单。
- 预览：恢复居中的桌面画面（按录制几何等比适配），移除鼠标轨迹、常驻“当前动作”条和参考图说明条；无参考图时显示“添加预览背景”，有图时提供右上角更换入口。指针与点击反馈改为覆盖层，演示表单可以显示在其下。
- 任务侧栏：录制过的任务使用循环图标、未录制使用文件夹图标；显示“6.8 秒 / 尚未录制”，不再显示动作数量；选中任务提供重命名/删除菜单；底部改为“本地任务”。
- 录制内容：标题只显示动作数量，恢复 `+`（插入等待）和 `×`（收起）按钮；移除底部提示条和头部“插入文本”；动作行时间改为 `mm:ss.xx`，悬停提供 `⋯` 菜单，右键菜单与原型一致。
- 时间线：恢复“适合窗口”图标按钮；刻度改为 `m:ss`；移动动作改为指针标记 + 下划线，点击动作区分左/右/中键与单击/双击，等待块显示“1 秒”；移除标题旁的缩放说明和百分比。缩放上限与原型一致为 8 倍。
- 任务头部：移除“已保存”和“空闲/录制中”徽标；恢复演示返回箭头与“独立练习，不会改动你的任务”说明；保留文档要求的循环次数、“执行到系统”和快捷键设置。
- 编辑窗口：按原型改为类型图标 + X/Y + “相对于屏幕左上角” + 预览选点；移动耗时和等待时长统一按秒填写，点击方式、滚动量单位、文本/按键字段名称与原型一致；联动点击默认勾选，仅在存在后续点击时显示。
- 帮助：引导改为原型的三段式对话框（任务区域 / 连续录制 / 回放与编辑 + 工作区缩略图），不再用简单四步弹窗和真实界面高亮；演示改为画布内“新建联系人”练习表单，示例录制更新为原型的 6.8 秒动作序列，移除画布外练习条、演示提示条和“演示”徽标。演示中系统录放仍保持关闭，因此原型画布内录制本身没有移植。
- 菜单与对话框：文件菜单移除“保存任务”和“预览参考图”（参考图从预览和任务菜单进入）；关于页移除诊断信息；移除前端“上次执行报告”入口与 `ExecutionReportPanel`，后端报告数据仍保留用于验证；新建任务名称上限与占位提示、快捷键参考列表按原型调整。
