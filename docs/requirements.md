# Repeat 功能需求

版本：需求基线 v0.2。更新日期：2026-10-25。

本次确认：先完成 Windows，再交付 Linux X11；Wayland 单独验证。首版手动导入预览参考图；键盘先忠实录放按键，新增或编辑文本单独处理。实施顺序与阶段验收见[实施计划](implementation-plan.md)。

本文将用户已确认的功能、交互和边界整理为后续开发依据。[交互原型](index.html)用于解释界面；原型内可演示的操作不等于原生能力已经交付。[技术方案与选型](decisions/0001-technical-selection.md)负责实现建议和平台验证。

## 1. 产品目标与用户

用户要的是一个桌面端“按键精灵”：在指定的开始、停止之间连续监听系统键鼠操作，保存动作、轨迹和时间关系，允许编辑后再次执行，以减少重复劳动。

例如，从 10:00 开始，到 10:03 停止，形成一段约三分钟的录制。回放应复现这段操作及原有停顿，而不是要求用户手工逐条搭建流程。

- 主要平台：Windows、Linux 桌面。交付顺序已确认先 Windows、再 Linux X11；Wayland 单独验证，不作为 Windows/X11 交付前置条件。具体系统版本、架构及发行版仍需确定。
- 技术方向：Tauri + Rust；当前阶段先确认原型和文档。
- 使用人群：具备普通电脑使用能力、约高中毕业知识水平的用户，不要求编程或 RPA 经验。
- 界面适配对象是不同尺寸的桌面窗口，不设计手机界面。

影刀 RPA 的参考价值是清楚的动作表达、简洁的工作区和双击编辑；Cap 的参考价值是连续、清晰的时间线。产品工作方式仍是连续录制真实系统输入。

## 2. 核心对象和术语

| 对象 | 含义 |
| --- | --- |
| 任务 | 用户管理的一项工作；一个任务对应一段录制及其编辑结果 |
| 原始输入事件 | 后端实际收到的移动、按下、抬起、滚轮等输入及时间信息 |
| 动作 | 面向用户展示、选择和编辑的一组相关事件，例如一次双击或一段鼠标移动 |
| 原始停顿 | 用户录制时实际没有操作的时间，属于录制内容 |
| 插入等待 | 用户在编辑时明确添加的延时，区别于录制本身已有的停顿 |
| 预览 | 在本工具中查看指针、动作与时间的对应关系 |
| 系统回放 | 向操作系统发送输入，实际重复操作；原型目前只模拟预览 |

预览与系统回放需要明确区分，避免用户只是查看录制，却意外操作其他应用。最终执行入口的具体命名见第 7 节待确认事项。

## 3. 已确认的功能与交互

### FR-01 多任务管理

- 左侧是任务区域，右侧展示当前任务的录制、预览和编辑内容。
- 支持管理多个任务；各任务的录制和编辑结果独立保存。
- 切换任务时加载对应数据，不能串用其他任务的动作或预览状态。
- 一个任务对应一段录制，不把多个任务混成一条时间线。

新建、重命名、保存等入口已在原型体现。重录时如何保留旧版本、删除恢复期限等规则见第 7 节，不能据此默认为无限历史版本。

### FR-02 连续录制系统键鼠输入

- 用户开始后，持续记录系统输入；停止后形成完整录制。
- 录制作用于支持的桌面会话，不能仅监听本工具窗口或网页元素。
- 记录事件先后顺序、发生时间，以及操作之间原有的间隔。
- 后续回放需要用到的按下、抬起和按住状态必须保留，不能只保存展示用的动作标题。

| 输入 | 需要表达的内容 |
| --- | --- |
| 鼠标移动 | 起止位置、收到的移动轨迹、移动耗时 |
| 鼠标点击 | 左键、右键、中键；单击、双击及实际按下/抬起顺序 |
| 鼠标滚轮 | 向上/向下、滚动量，以及数据实际使用的单位 |
| 键盘 | 普通输入、单键、组合键及相应按下/抬起、重复输入信息 |

键盘输入是已确认需求；“物理按键序列”“可显示的字符”和“输入法最终提交的文本”不是同一种数据。中文输入法等场景的文本还原能力必须验证，不能把无法确定的内容当成已经识别到的文本。

首版已确认以忠实录放实际按键为基础，不要求自动识别输入法最终提交的中文；用户新增或编辑文本作为独立的明确文本输入处理。相同按键在不同布局、输入法和候选状态下可能产生不同结果，需记录适用环境并验证。

### FR-03 保持原节奏的系统回放

- 按录制顺序复现输入，默认保留原有轨迹、操作间隔和停顿。
- 用户希望回放响应及时、动作流畅，不能因界面更新或每步额外等待而越播越慢。
- 双击应回放实际的两次按下/抬起，组合键应保留正确顺序；不能用一个标题替代完整输入。
- 编辑新增的等待应生效，并与原始停顿区分。
- “低延迟”不等于承诺操作系统绝对零延迟。数值指标尚未由用户确认，测量提案见技术文档。

回放依赖目标应用、焦点、屏幕布局和输入环境。应用响应变慢时如何处理，见第 7 节；不能擅自把原样回放改成寻找控件、识别窗口或自动等待页面完成。

### FR-04 鼠标移动归并与终点编辑

- 保留底层收到的轨迹，但用户列表和时间线不逐个展示移动采样点。
- 一段相关移动以整体动作呈现，能直接选择、定位和编辑。
- 修改移动时，用户主要关心最终位置；不要求手工绘制或逐点调整轨迹。
- 可以编辑终点坐标、在预览中选点，以及修改移动耗时。
- 原型提供“同时修改紧接着的点击位置”。默认联动与解除联动的具体保存规则，应遵循明确的编辑结果，不静默移动其他无关动作。

### FR-05 双击编辑动作、插入等待

- 单击动作：选择并定位到对应回放位置，不常驻展开全部参数。
- 双击动作：在编辑窗口中修改参数；确认后生效，取消保留原数据。
- 支持在两个动作之间插入等待，也可以通过动作右键菜单在其后插入。
- 插入等待后，后续动作整体延后；原来的动作间隔仍然保留。

| 动作 | 编辑时需要呈现的参数 |
| --- | --- |
| 鼠标移动 | 终点 X/Y、预览选点、移动耗时、相关点击是否联动 |
| 鼠标点击 | 左/右/中键、单击/双击、点击位置 |
| 鼠标滚轮 | 方向、滚动量；单位明确，不能与方向含混在一个数值中 |
| 键盘输入 | 真实文本、按键或组合键，按相应输入类型编辑 |
| 等待 | 等待时长 |

### FR-06 录制内容的清楚表达

- 只展示能够由录制数据证明的事实，不推测目标是“姓名输入框”“提交按钮”等业务控件。
- 普通输入、单键和组合键统一使用键盘图标及“键盘输入”类别。
- 用一句说明突出实际内容，例如“输入文本 b”“按下 Tab”“按下 Ctrl + S”。
- 鼠标操作必须区分实际按键、单击/双击和滚轮方向，不能全用相同圆点与“单击”概括。
- 坐标、时间单位等参数主要服务编辑和定位，不把界面铺成常驻技术参数表。

### FR-07 预览、时间线和录制内容联动

- 三者使用同一个当前时间和动作选择状态。
- 播放、暂停、定位、拖动时间线后，指针位置、点击反馈和键盘反馈同步变化。
- 预览能够清楚表现鼠标移动及点击，不再与时间线割裂。
- 预览不显示“起点”、路径编号、“第一步/第二步”等额外标注。
- 预览底图必须说明实际来源；仅有键鼠输入时，不能假装已经取得其他软件的历史画面。
- 首版由用户手动导入参考图，不包含自动截图或同步屏幕录像；没有参考图时仍可查看轨迹及键鼠反馈。

### FR-08 连续时间线和缩放

- 鼠标、键盘及明确插入的等待沿同一时间轴对齐。
- 用连续轨迹区间、具体动作标记和按键内容表达时间关系，避免每个动作都切成独立大块。
- 密集时可以收起文字，但保留可辨识的操作标记及完整悬停信息。
- 点击或拖动可定位回放；时间轴上的动作仍可双击编辑。
- 时间线区域上滚放大、下滚缩小；缩放围绕鼠标指向的时间位置。
- 支持“＋ / −”缩放；原型已有的辅助交互为 Shift＋滚轮左右移动。
- 时间线内部的“适合窗口”控件恢复完整时间范围，录制进行中也应有效。
- 最后一个动作、结束标记应正确收在时间线范围内，不能产生“少录一段”的视觉缺口。

### FR-09 视图显示与隐藏

“视图”菜单包含两个独立开关：

| 菜单项 | 点击行为 |
| --- | --- |
| 录制内容 | 显示或隐藏录制内容区域 |
| 时间线 | 显示或隐藏整个时间线区域 |

**“视图 → 时间线”不执行“适合窗口”。** 缩放复位保留在时间线内部。隐藏面板应把空间还给预览，重新显示时不修改录制数据或当前播放时间。

### FR-10 独立使用演示与引导

- 帮助采用类似 VS Code 的菜单入口，“使用演示”放在帮助中。
- 进入使用演示前提供可跳过的漫游式引导，说明任务、录制、预览和编辑的使用方式。
- 使用演示是独立练习空间，示例录制、练习表单和练习数据与用户任务隔离。
- 退出演示回到原任务，不把演示内容加入真实任务列表。
- 引导从整体工作区设计出发，不依赖反复移动提示气泡来补救布局问题。

### FR-11 桌面应用体验

- 保持左侧任务、右侧工作区的桌面应用结构。
- 适配较大和较小的桌面窗口，核心操作可用；不新增手机导航或移动端布局。
- 简化文字和常驻工具，使用自然语言，不要求用户理解底层事件码或技术实现。
- 原型按最终产品的使用逻辑设计，示例内容只承担教学职责。

以下是验收要求，不表示原生功能已经通过测试。

| 编号 | 场景及预期 | 对应需求 |
| --- | --- | --- |

| AC-02 | 切换到其他应用完成操作；支持的平台仍能录制，而非只在 Repeat 内有效 | FR-02 |

| AC-04 | 一段包含大量移动事件的轨迹以整体动作展示，能直接修改终点，不铺成数百条步骤 | FR-04、FR-08 |
| AC-05 | 双击编辑后取消，原数据不变；确认后列表、预览与时间线呈现相同结果 | FR-05、FR-07 |
| AC-06 | 在动作之间加一秒等待，后续动作与总时长增加一秒，原停顿不被吞掉 | FR-03、FR-05 |
| AC-07 | 两个任务各保存一段不同录制；切换、编辑或进入练习均不串数据 | FR-01、FR-10 |
| AC-08 | 单击动作或拖动时间轴，预览中的指针和键鼠反馈对应相同时间 | FR-07、FR-08 |
| AC-09 | 滚轮上/下与“＋ / −”可缩放，缩放不改变动作时间；适合窗口可看到完整录制 | FR-08 |
| AC-10 | 通过视图菜单分别隐藏和显示录制内容、时间线；预览获得空间，数据、播放位置不变 | FR-09 |
| AC-11 | 从帮助进入引导，跳过或完成后进入独立演示；退出恢复原任务 | FR-10 |
| AC-12 | 较小桌面窗口中仍能选择任务、操作录制/回放和编辑；不出现手机式布局 | FR-11 |
| AC-13 | 列表不出现录制数据无法证明的输入框/按钮名称；预览没有起点与步骤编号叠加 | FR-06、FR-07 |
| AC-14 | 录制超过五秒、时间线放大并移动后，内部“适合窗口”仍能完整显示当前录制 | FR-08 |

性能需按技术文档中的测量提案验收，区分引擎发起输入的时间偏差与目标软件实际响应时间。

## 5. 工程补充建议

以下是让已确认需求可靠落地的建议，尚不作为用户新增确认的功能清单：

- 原始录制与编辑结果分开保留，提供必要撤销或恢复；不静默覆盖已有任务内容。
- 系统执行提供不依赖窗口焦点的停止手段，停止后处理本工具尚未释放的注入按键。
- 录制、预览、系统执行状态明确，避免重复执行、录回自己的输入或误操作其他应用。
- 权限不足、队列溢出、输入注入失败、显示布局变化时给出明确状态，不假报成功。
- 任务在本地存储；录制内容可能包含敏感文本，不在普通日志中输出完整键盘输入。

## 6. 当前实现边界

当前可核查的交付物是 [HTML 原型](index.html)。它具备任务、动作编辑、预览与时间线等模拟交互；脚本明确将捕获范围限制在画布内。

原型不能证明以下能力已经完成：系统级监听与输入注入、原生低延迟表现、完整中文输入法文本采集、所有 Linux 会话兼容、多显示器坐标一致性。

## 7. 待确认事项

这些问题需要在实现对应能力或给出兼容性承诺之前确定；按实施计划分阶段定稿，不要求全部问题同时阻塞 Windows 首轮验证。它们不改变上述已确认的产品目标。

| 事项 | 需要确定的内容 |
| --- | --- |
| 平台支持矩阵 | 在先 Windows、再 Linux X11 的顺序下，明确具体版本、架构、发行版及测试环境；Wayland 单列验证环境 |
| 输入法与字符输入 | 在按键录放与明确文本输入分开的前提下，确定支持的布局、输入法及文本输入适用的目标应用 |
| 实机执行入口 | 如何区分预览与系统回放；全局启动/停止快捷键、人工介入与中止规则 |
| 任务数据管理 | 重录替换/版本保留、删除恢复、导入导出是否进入首版 |
| 重复执行规则 | 循环次数、无限循环、任务间衔接与失败后的处理方式 |
| 性能与规模 | 可接受的时间偏差、最长录制时长、任务数量与内存/磁盘预算 |
| 额外鼠标能力 | 拖拽的独立编辑方式、水平滚轮、侧键是否列入首版；原始按住/抬起不能因展示归并而丢失 |
